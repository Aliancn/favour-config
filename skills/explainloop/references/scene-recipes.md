# From article relationship to scene

Choose the **relationship** before choosing a palette. Make a five-line scene brief for each GIF: source claim and status; focal object; visible before/after; reading order; final takeaway. State what the motion reveals that a still frame would not. For longer articles, outline candidate topics internally and pick the strongest supported relationship. Ask the user only when the requested passage or a material fact cannot be resolved from the source.

Before writing scene code, sketch two short alternatives in words or ASCII. Change the *composition*, not merely the color: for example, a document-first annotated specimen versus a split before/after transformation. Choose the alternative whose focal object and final claim remain clear at article width. First describe the complete outcome frame, including its reading order and direct labels. Then plan the earlier states that lead to it. Record a compact direction card: subject cue, type roles, surface roles, object fields, one main motion, and one tempting but unsupported visual to reject. This adapts the design-brief and self-critique workflow of [Anthropic's frontend-design skill](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md) and the static-first layout principle of [animated-infographic](https://github.com/iart-ai/data-animation-skills/blob/main/skills/animated-infographic/SKILL.md). The card and sketches are internal working notes, not an approval gate.

When a request contains several GIFs, choose the batch's preset and shared visual tokens once after selecting topics. Give each topic its own focal composition, but keep the background character, colors, font roles, strokes, corners, component rendering, and motion rhythm recognizably from the same set. Aspect-ratio versions inherit the same batch style. A chart may add a semantically necessary series color within the chosen palette; that does not justify changing the whole scene preset. If the user explicitly asks for a mixed-style collection, follow that request.

Use one of these starting compositions, then adapt geometry and copy to the evidence. The linked scenes are worked examples, not layouts to trace.

| Relationship in the text | Focal composition and visible change | Example |
| --- | --- | --- |
| Capacity or attention limit | One dominant value or constraint beside a small set of concrete tasks; move focus among tasks rather than adding unrelated progress bars | `assets/examples/showcase/01-editorial-paper.scene.mjs` |
| Measured comparison | Directly labeled marks with the unit close by; animate from a valid baseline and separate different metrics | `assets/examples/showcase/04-data-newsroom.scene.mjs` |
| Route or architecture | Give source, decision point, and destination distinct regions; animate the packet along the actual causal path | `assets/examples/showcase/10-router-atelier-16x9.scene.mjs` |
| Change over time | Large dates, evidence panels with meaningful content, and a marker that follows chronological order | `assets/examples/showcase/06-archival-timeline.scene.mjs` |
| UI or document transformation | Show the source object's useful fields, the extracted fact, and the resulting object's state; keep synthetic UI labeled | `assets/examples/showcase/07-refined-email.scene.mjs` |
| One source or artifact | Allocate most space to the source; reveal the relevant detail before the interpretation | `assets/examples/showcase/11-museum-gallery.scene.mjs` |
| Short conceptual contrast | Let type and one color region carry the distinction; use only a few labels | `assets/examples/showcase/13-chromatic-poster.scene.mjs` |

Keep the scene's first frame meaningful. Place the main claim or object before metadata; give related labels shared alignment. Order reveals by meaning: show the object, then its change, then the label that explains the result. Keep one dominant moving event at a time unless simultaneous motion is the actual relationship. If the article has no concrete subject for a component, simplify rather than populating generic empty cards. Match the article's factual status: a proposed workflow must not look completed, and an illustrative UI must not impersonate a real product. For different aspect ratios, preserve the evidence and action sequence but rearrange the composition.

`assets/examples/showcase/17-superagent-router.scene.mjs`, `18-superagent-tokens.scene.mjs`, and `19-superagent-filters.scene.mjs` form one same-article, same-style batch. They show three distinct compositions for architecture, measured comparison, and event filtering; use them to inspect batch coherence rather than as templates to copy.

## Quality-first production

1. Write each scene from its brief and chosen thumbnail. Choose a visual family from [design-directions.md](design-directions.md) and a composition from [backgrounds.md](backgrounds.md), while applying the batch's already chosen style. Keep copy short enough for the intended article width.
2. For two or more scenes, run `scripts/check-batch.mjs` on all scene sources before rendering. It rejects differing presets or resolved shared style tokens; it cannot detect colors or fonts hardcoded inside `draw()`.
3. If the active agent can **actually perceive image pixels**, run `scripts/preview.mjs --temporal-strip` for each scene. Inspect the four key frames and the eight-frame temporal strip; focus on reading order, momentary overlap, short-lived false states, and loop reset. For a batch, run `scripts/preview-batch.mjs` with the same scene list to compare outcome frames on one sheet. Check background, type, component details, and color roles, including values hardcoded inside `draw()`. Revise concrete defects, up to two visual revision rounds. Do not use Playwright for this SVG/GIF workflow.
4. If the active agent cannot perceive image pixels, skip preview and all visual-review claims. Use the same scene briefs and batch style, then render and run `scripts/inspect.mjs` for technical validation. State plainly that visual review was unavailable.
5. Render the final GIFs only after the applicable review path. A technically valid GIF is not proof of visual quality; do not represent the no-vision path as equivalent to visual revision.

The preview command samples opening, action midpoint, readable outcome, and the last frame before the loop. `--temporal-strip` adds up to eight evenly spaced frames; inspect the actual GIF if a brief transition falls between samples. Batch preview places each scene's outcome frame on a neutral panel so aspect ratios can be compared together. Its default display width approximates article use: 720 px landscape, 480 px square, 360 px portrait. Pass `--display-width` when the actual embed width is known. Preview files are temporary review artifacts; keep the delivered scene and GIF editable and uncluttered. For demonstrated defects and repairs, use [failure-cases.md](failure-cases.md).
